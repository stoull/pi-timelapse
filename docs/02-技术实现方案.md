# Raspberry Pi + Camera Module 3 延时摄影工具：技术实现方案

> 视角：负责把拍摄契约落成可长期运行系统的工程师  
> 对齐文档：[01-延时摄影设计方案.md](./01-延时摄影设计方案.md)  
> 目标：可配置、可恢复、可远程抽检、可合成预览；天空、植物与日常起居共用一套程序，用配置区分行为

---

## 1. 设计目标与非目标

### 1.1 目标

- 以 **项目（Project）** 为中心：模式、间隔、窗口、相机锁定参数、输出路径一次性写死。
- 拍摄进程 **开机自启、掉电续拍、不覆盖已有帧**。
- 相机控制基于 **Picamera2 + libcamera**（Camera Module 3 / IMX708）。
- 提供本机 CLI 与局域网 Web 面板（预览、状态、启停）。
- 将 JPEG/DNG 序列合成为预览或成片（ffmpeg）。
- 磁盘、相机、时钟异常可观测。

### 1.2 非目标（首期不做）

- 云端相册、手机 App 商店发布。
- 实时云层 AI 加密间隔（可作为 v2 插件）。
- 在 Pi 上做电影级调色与 LRTimelapse 全集。
- Windows 桌面版拍摄端。

```

                    │  config/*.yaml  项目配置     │
                    └─────────────┬───────────────┘
                                  │
┌──────────┐   REST/WS    ┌───────▼────────┐   控制    ┌─────────────────┐
│ Web UI   │◄────────────►│  timelapse-d   │◄────────►│ CameraService   │
│ (浏览器)  │   状态/预览   │  (主守护进程)   │           │ Picamera2       │
└──────────┘              └───────┬────────┘           └────────┬────────┘
                                  │                             │
                    ┌─────────────┼─────────────┐               │ JPEG/DNG
                    ▼             ▼             ▼               ▼
              Scheduler     StorageGuard    Health            data/<project>/frames
              (窗口+间隔)    (磁盘阈值)      (NTP/温/错)              │
                                                                  ▼
                                                           EncodeJob
                                                           (ffmpeg)
```

**进程模型（推荐）**

| 进程 | 职责 | 运行方式 |
| --- | --- | --- |
| `timelapse-d` | 读配置、调度快门、写盘、维护状态 | systemd `Restart=always` |
| `timelapse-web` | FastAPI/uvicorn，只调 daemon 的 API 或共享 Unix socket | systemd，可与 daemon 同机 |
| `timelapse` CLI | 创建项目、拍测试帧、合成、校准对焦 | 用户手动 / ssh |

首期可将 Web 与 daemon 做成 **同一进程两个 asyncio 任务**，减少 IPC。存储压力大时再拆。

## 3. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11+ | Picamera2 官方路径，Pi OS 友好 |
| 相机 | `picamera2` | Module 3 AF/HDR/controls 完整 |
| 配置 | YAML + Pydantic 校验 | 拍摄契约可读、启动即失败于错误配置 |
| Web | FastAPI + 极简 HTML/HTMX 或 Vue | 局域网够用，预览用 MJPEG 或 JPEG 轮询 |
| 调度 | 自研间隔循环 + `zoneinfo` + `astral`（日出日落） | cron 不够（亚分钟间隔、太阳角窗口） |
| 成片 | ffmpeg 子进程 | H.264/H.265、抽帧预览成熟 |
| 服务 | systemd | 开机、看门狗、日志 journald |
| 状态 | `state.json` + 内存 | 崩溃恢复、Web 读取 |
| 测试 | pytest + 假相机后端 | 开发机无 CSI 也能测调度与命名 |

不建议用 `raspistill` / 旧 `picamera`（Bullseye/Bookworm 已转向 libcamera）。

## 5. 配置模型（拍摄契约）

```yaml
# 示例：data/grow-basil-2026/project.yaml
schema_version: 1
project_id: grow-basil-2026
mode: grow                 # sky | grow | life
created_at: "2026-08-21T10:00:00+08:00"

capture:
  interval_sec: 900        # 15 分钟；sky 常用 1–30
  still_config:
    main_size: [2304, 1296]   # 16:9 接近 2.8K，可改为 4608x2592 或 1920x1080
    format: JPEG              # JPEG | DNG | JPEG+DNG
    jpeg_quality: 95
  overlay_timestamp: false

window:
  type: solar              # always | clock | solar
  latitude: 31.23
  longitude: 121.47
  timezone: Asia/Shanghai
  solar:
    start: sunrise
    start_offset_min: -20
    end: sunset
    end_offset_min: 20
  # clock 示例：
  # type: clock
  # start: "06:00"
  # end: "22:00"

camera:
  lens: standard           # 仅文档标记
  af_mode: manual          # manual | auto_once
  lens_position: 0.0       # 无穷远附近需现场校准写入
  ae_enable: false
  exposure_time_us: 2000   # 1/500s
  analogue_gain: 1.0
  awb_enable: false
  colour_gains: [1.6, 1.5] # R, B；或 colour_temp_k: 5200（若驱动支持则转换）
  hdr: false               # 开启后仍须固定，禁止运行中切换
  camera_led: false        # 起居必须关；避免红点入画、避免被拍者看镜头

# 起居可选：夜晚第二套冻结参数（与 camera 结构相同）
# camera_night:
#   ae_enable: false
#   exposure_time_us: 500000    # 0.5s
#   analogue_gain: 2.0
#   awb_enable: false
#   colour_gains: [1.4, 1.8]
# night_switch:
#   type: clock                 # clock | solar
#   at: "18:30"                 # 当天切到 camera_night
#   solar_elevation_deg: 6      # 若 type=solar：太阳低于该高度则用夜景

storage:
  root: /mnt/ssd/timelapse
  min_free_gb: 5
  mkdir_by: day            # none | day | session

encode:
  fps: 24
  preview_height: 1080
  codec: libx264
```

校验规则（Pydantic）：

- `mode=sky` 且 `interval_sec > 60` 时告警（允许，但不推荐）。
- `mode=grow` 且 `interval_sec < 60` 时告警。
- `mode=life` 且 `interval_sec > 120` 时告警（人会从时间轴上消失）；`life-activity` 类项目 `interval_sec > 4` 时软警告。
- `mode=life` 且 `window.type=always` 时硬警告（起居不应整夜对着空房间拍，除非 `allow_always=true`）。
- `ae_enable=true` 与 `awb_enable=true` 同时开启时 **硬警告**（可配置 `allow_auto=true` 才通过）。
- `main_size` 必须是 Module 3 支持的模式表中的一组。
- 若配置了 `camera_night`，必须同时给出 `night_switch`（`clock` 时刻或太阳高度），运行中只允许在这一边界切换整套锁定参数，禁止逐帧插值。

## 6. 相机子系统

### 6.1 生命周期

```
open camera
  → 配置 still / preview 流
  → 应用 controls（AF/AE/AWB）
  → 若 af_mode=auto_once：对焦成功后切 manual 并记录 lens_position
  → 丢弃前 3～8 帧（AE 若开启时收敛；锁定模式下也用于传感器稳定）
  → 进入 capture loop
close on stop / fatal error
```

长时间运行建议：**不必每张都 close/open**。保持相机常开，仅在窗口关闭（夜晚）时 `stop` 以降低发热；窗口打开再 `start`。植物 15 分钟间隔也可常开，实现更简单，夏天注意温度。起居 1～4 秒间隔等于持续拍摄，必须监控 SoC 温度；超过阈值先关 Web 预览，再考虑把 still 分辨率降到配置允许的下限（只能在新 session，不能运行中改）。

`camera_led: false` 通过 `libcamera` / 设备树或 Picamera2 的 LED 控制关闭模块红灯。起居项目启动时若 LED 仍亮，健康检查记一条警告。

### 6.2 Picamera2 要点

- Still：`create_still_configuration(main={...})`，需要预览时加 `lores`。
- Module 3 AF：`AfMode`、`LensPosition`、`AfTrigger`。锁定后把实际 `LensPosition` 写回 `state.json`，便于崩溃恢复。
- 曝光：`AeEnable=False`，`ExposureTime`，`AnalogueGain`。
- 白平衡：`AwbEnable=False`，`ColourGains`。
- 捕获：`capture_file(path)` 或 `capture_request()` 以便写 EXIF。

封装接口：

```python
class CameraService:
    def start(self, cfg: CameraConfig) -> None: ...
    def capture_still(self, path: Path) -> CaptureMeta: ...
    def snapshot_jpeg(self) -> bytes: ...   # Web 预览
    def autofocus_once(self) -> float: ...  # 返回 lens_position
    def stop(self) -> None: ...
```

开发机注入 `FakeCameraService` 写纯色帧，保证 CI 可跑。

### 6.3 对焦校准 CLI

```
timelapse focus --project grow-basil-2026
```

流程：开预览 → 用户 SSH 或 Web 点「对焦」→ `auto_once` → 打印并写入 `lens_position` → 锁定。天空项目提供 `focus --infinity` 经验值，仍要求人工看图确认。

## 7. 调度算法

### 7.1 间隔补偿

错误做法：`sleep(interval)`，拍照 200ms 后实际间隔被拉长。

正确：

```
next_t = t0
while running:
    now = monotonic_or_utc()
    if now < next_t:
        sleep(next_t - now)
    if in_window(wall_clock):
        capture()
    next_t += interval
    if next_t < now:          # 拍照超时或系统休眠
        skip_missed_slots()   # 不追赶连拍，跳到最近的未来槽
```

使用 **墙上时钟** 判断窗口与文件名，使用 **monotonic** 防 NTP 回拨导致 sleep 异常。NTP 阶跃时：记录健康事件，按新墙钟对齐下一个 slot，不删旧文件。

### 7.2 拍摄窗口

| type | 逻辑 |
| --- | --- |
| `always` | 永远允许 |
| `clock` | `[start, end)`，跨午夜要拆两段 |
| `solar` | 用 `astral` 算当日 sunrise/sunset，加减 offset |
| `event` | 仅在 CLI/Web 手动 start 与 stop 之间允许；适合 `life-activity` 一顿饭。进程崩溃后不自动继续拍，除非配置 `resume_event: true` |

窗口外：不拍照，可停相机。窗口边界处 **正在进行的一张拍完再停**。

`night_switch`（仅 `mode=life` 需要时）：仍在拍摄窗口内，但在边界时刻把 `CameraService` 从 `camera` 整表切换到 `camera_night`（或反向）。切换后丢弃 3 帧再写入序列，避免管道刷新那几张脏帧。禁止在两次快门之间对 ExposureTime 做插值——那是后期 Holy Grail 的工作，不在 Pi 上做。

太阳角计算缓存到当天日期，避免每帧算一次；日期变化时刷新。

### 7.3 错过的槽

植物 15 分钟一格：停电 2 小时 → 恢复后从「下一个整格」继续，文件名仍用实际拍摄时间，不伪造未拍帧。成片允许时间轴上有跳跃（比插入黑帧更诚实）。可选后续：生成 `gaps.json` 供后期处理。

## 8. 存储与命名

```
{root}/{project_id}/frames/2026-08-21/frame_20260821_063015.jpg
```

- `mkdir_by: day` 避免单目录数十万文件。
- 文件名 **UTC 或本地时区必须在 project.yaml 中固定**，推荐本地时区墙钟，方便人读。
- 写入采用 `*.jpg.tmp` → `fsync` → `rename`，防止掉电半截 JPEG。
- EXIF 写入：DateTimeOriginal、ImageDescription=`project_id`、自定义注释 JSON（exposure、gain、lens）。

`StorageGuard`：`shutil.disk_usage`，`free < min_free_gb` → 停止捕获、状态 `disk_full`、Web 红条。不自动删除原图（防止误删几个月植物）。预览视频可标为可删缓存。

## 9. 守护进程与恢复

`state.json` 示例：

```json
{
  "status": "capturing",
  "last_frame": "frames/2026-08-21/frame_20260821_141500.jpg",
  "last_ok_at": "2026-08-21T14:15:00+08:00",
  "consecutive_failures": 0,
  "lens_position": 4.12,
  "frames_total": 3821
}
```

systemd：

```
[Service]
Type=simple
ExecStart=/usr/bin/timelapse daemon --project /mnt/ssd/timelapse/grow-basil-2026/project.yaml
Restart=always
RestartSec=5
Nice=5
```

启动顺序：

1. 等待时间同步（`timedatectl` 已 NTP 或 RTC 有效），超时则进入 `clock_unreliable` 但仍可拍，文件名加警告日志。
2. 校验磁盘、相机。
3. 加载冻结配置与 `lens_position`。
4. 从下一个 slot 开始。

连续失败 N 次（默认 5）：重启相机管道；再失败则 `status=error` 等待人工，避免死循环打满日志。

## 11. 合成管线

```
ffmpeg -y -framerate 24 \
  -pattern_type glob -i 'frames/**/*.jpg' \
  -vf "scale=-2:1080,format=yuv420p" \
  -c:v libx264 -crf 18 -pix_fmt yuv420p \
  previews/preview.mp4
```

注意：

- glob 顺序依赖文件名时间戳排序，禁止 `img001` 无前导零方案。
- 天空单场目录合成；植物可按日期分段合成再拼接。
- 起居默认 **按日合成** 再可选拼接成周片；一天 5 千～1 万张，不要对整个项目 glob 一次。
- Pi 上 4K 全长编码慢，默认预览 1080p；最终 4K 建议拷到电脑编码。
- 可选 `libx265` 换体积，Pi 5 更合适。

封装 `EncodeJob`：后台线程/子进程，状态 `encoding` / `done` / `failed`。

## 14. 关键代码骨架（示意）

调度主循环伪代码：

```python
async def run_capture_loop(project: Project, cam: CameraService) -> None:
    interval = timedelta(seconds=project.capture.interval_sec)
    next_slot = align_next(datetime.now(project.tz), interval)
    failures = 0
    while not stop_event.is_set():
        await sleep_until(next_slot)
        if not project.window.contains(datetime.now(project.tz)):
            next_slot += interval
            continue
        if not storage.has_space(project.storage.min_free_gb):
            state.set("disk_full")
            await wait_until_space_or_stop()
            continue
        path = layout.frame_path(project, datetime.now(project.tz))
        try:
            cam.capture_still(path)
            failures = 0
            state.record_ok(path)
        except CameraError:
            failures += 1
            log.exception("capture failed")
            if failures >= 5:
                cam.reopen()
            if failures >= 10:
                state.set("error")
                await wait_manual_resume()
        next_slot += interval
        now = datetime.now(project.tz)
        if next_slot < now:
            next_slot = align_next(now, interval)
```

相机锁定：

```python
def apply_lock(picam, c: CameraConfig) -> None:
    controls = {
        "AeEnable": c.ae_enable,
        "AwbEnable": c.awb_enable,
        "AfMode": 0 if c.af_mode == "manual" else 1,  # 以 picamera2 枚举为准
    }
    if not c.ae_enable:
        controls["ExposureTime"] = c.exposure_time_us
        controls["AnalogueGain"] = c.analogue_gain
    if not c.awb_enable:
        controls["ColourGains"] = tuple(c.colour_gains)
    if c.af_mode == "manual":
        controls["LensPosition"] = c.lens_position
    picam.set_controls(controls)
```

具体枚举值以实现时 `picamera2` 文档/头文件为准，禁止把示意数字直接当生产常量。

## 15. 部署与现场规程

### 15.1 系统准备

- Raspberry Pi OS Bookworm 64-bit
- `apt install python3-picamera2 python3-libcamera ffmpeg python3-venv`
- SSD：`/mnt/ssd`，`fstab` 用 UUID；`noatime`
- 关闭不需要的桌面特效；若无头跑，用 Lite 镜像
- 开启 I2C 仅当使用 RTC
- `dtparam=camera` 走 libcamera 默认即可

### 15.2 现场校准顺序（软件强制检查表）

1. `init` 从 preset 复制项目  
2. 构图、固定螺丝  
3. Web/CLI 预览，水平  
4. `focus` 锁定，100% 看图  
5. 用测光/直方图调 `exposure_time_us` / `gain`，关闭 AE  
6. 拍 20～50 张测试，`encode` 看闪烁与抖动  
7. 写入冻结 `project.yaml`，`systemctl enable --now timelapse`  
8. 模拟拔电一次，确认续拍与时间正确  

### 15.3 时间

- 联网：`systemd-timesyncd` 或 chrony  
- 离线：DS3231 RTC，`hwclock` 同步  
- 拍摄进程启动若 offset 过大只告警不擅自改历史文件名

## 17. 风险与工程对策

| 风险 | 对策 |
| --- | --- |
| SD 卡写坏 | 根文件系统只读可选；素材只写 SSD |
| CSI 偶发挂死 | 超时 + 进程级重启相机；systemd 拉起整个 daemon |
| 发热降频 | 夜间停流；壳体通风；预览默认关 |
| 依赖版本 | 锁定 `picamera2` 于 Pi OS 包，不混 pip 与系统 libcamera |
| 配置被改 | 运行中只读冻结副本；改参必须停拍并新开 session 或明确 `amend` 命令 |
| 16:9 与传感器 4:3 | 在 still 配置里直接选 16:9 尺寸，预览叠加安全框 |

## 18. 技术结论

实现上把系统拆成 **冻结的项目配置、带窗口的精确调度器、可锁定的 Picamera2 服务、防掉电写盘、可恢复的 systemd 守护进程、局域网预览与 ffmpeg 合成**。

与拍摄设计一一对应的工程约束是：

- 自动曝光/白平衡/对焦默认关闭，只提供「校准一次再锁定」。  
- 间隔用绝对时间槽，不追赶漏拍。  
- 原图是唯一资产，视频只是导出物。  
- 植物级长期运行的优先级是：时钟、磁盘、恢复、告警，然后才是 12MP 与 HDR。  
- 起居额外：关 LED、隐私暂停留缺口、按日合成、日夜参数只允许整表切换。

建议落地顺序：**M0 在实机打通锁定拍照 → M1 加上太阳窗口、起居预设与合成 → M2 加上 Web 抽检**。在 M1 完成前不要开始以周为单位的植物项目或起居周拍。
