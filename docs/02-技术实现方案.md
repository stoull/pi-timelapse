## 1. 已实现与明确不做

### 已实现

- 以 **项目** 为中心：方案 YAML 复制进该项目的 `project.yaml`，相机与间隔按项目保存。
- **单一进程**：FastAPI + uvicorn + `CaptureRuntime`（asyncio）。可用 systemd 拉起 `timelapse serve`，或用 Docker Compose 跑同一入口。
- 相机：**Picamera2 + libcamera**，官方 Camera Module 3 / IMX708。
- 局域网 Web：项目、预览、调参、启停、定时、相册、导出。
- JPEG 序列 + ffmpeg **H.264 MP4**（concat + `-r` 与所选 fps 一致）。
- 磁盘阈值停拍；拍摄中崩溃后按 `state.json` 尝试续拍；定时预约可跨重启。
- 开发机 **pytest + FakeCamera**，不依赖 CSI。

### 首期不做（设计稿里有、代码未做）

- DNG / JPEG+DNG、独立 CLI（init / daemon / encode / focus）。
- WebSocket / WebRTC / MJPEG 推流（预览是 JPEG 轮询）。
- 登录认证、公网账号；H.265；云端相册。
- 运行中按太阳高度切换夜景（夜景字段在 schema 中预留，`night_switch_at` 为钟点）。
- 90° / 270° 旋转（只支持 **0° 与 180°**）。

## 2. 进程与数据流

```
浏览器  ──HTTP──►  uvicorn  timelapse.web.app
                              │
                    CaptureRuntime（拍摄循环、定时、调参锁）
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        CameraService    Storage / 相册    EncodeManager
        Picamera2        JPEG 按日目录      ffmpeg 子进程
              │
              ▼
     <storage.root>/<project_id>/frames/...
```

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| 入口 | `src/timelapse/cli.py` | `serve`、`check-camera` |
| Web | `src/timelapse/web/app.py` | REST + Jinja 首页 |
| 运行时 | `src/timelapse/runtime.py` | 状态机、窗口、槽位、预览与拍摄互斥 |
| 相机 | `src/timelapse/camera/service.py` | still + lores、controls、180° transform |
| 调参说明 | `src/timelapse/camera/tuning.py` | 前端字段元数据 |
| 项目 | `src/timelapse/project.py` | 预设、注册表、`project.yaml` |
| 存储 | `src/timelapse/storage.py` | 路径、空间、相册、导出文件 |
| 调度 | `src/timelapse/schedule/` | `next_slot` / `advance_slot`、窗口 |
| 导出 | `src/timelapse/encode.py` | concat、缩放、ASS 水印 |
| 系统 | `src/timelapse/system.py` | CPU / 内存 / 温度 |

systemd：`systemd/timelapse.service`（与 `timelapse-docker.service` 互斥）  
- 用户 `pi`，组 `video`  
- `WorkingDirectory=/opt/pi-timelapse`  
- `ExecStart=.../timelapse serve --host 0.0.0.0 --port 8080 --state-dir /var/lib/pi-timelapse`  
- `TIMELAPSE_APP_ROOT=/opt/pi-timelapse`

Docker：`Dockerfile` + `docker-compose.yml`  
- 镜像内同样 `timelapse serve`，venv 带 `--system-site-packages` 以使用系统 `python3-picamera2`  
- privileged + 挂载 `/dev`、`/run/udev`、`/mnt`、`/media`  
- 状态目录 bind 到宿主机 `/var/lib/pi-timelapse`（可用 `TIMELAPSE_STATE_HOST` 改）

环境变量：

| 变量 | 含义 |
| --- | --- |
| `TIMELAPSE_STATE_DIR` | 项目注册表（`active_project`、`project_roots.yaml`） |
| `TIMELAPSE_APP_ROOT` | 仓库根，用于找 `config/presets` |
| `TIMELAPSE_PRESETS` | 可覆盖预设目录 |
| `TIMELAPSE_HOST` / `TIMELAPSE_PORT` | `serve` 监听地址；Docker / 环境变量可覆盖 CLI 默认值 |

照片不在状态目录里，而在各项目 `storage.root / project_id`。

## 4. 配置模型（落地）

Pydantic：`ProjectConfig`（`src/timelapse/config_schema.py`）。

要点：

- `mode`：`sky` | `grow` | `life`
- `capture.interval_sec`：大于 0，不超过 86400
- `still_config.main_size` 仅允许：`(1920,1080)`、`(2304,1296)`、`(3840,2160)`、`(4608,2592)`；`jpeg_quality` 70–100
- `window.type`：`always` | `clock` | `solar` | `event`；`solar` 需要经纬度；时区用 `zoneinfo`
- `camera.rotation`：`0` 或 `180`；读入时 `90`/`270` 收成 `0`
- `storage.root` 必须绝对路径，禁止 `/`、`/etc`、`/usr`、`/boot`
- `encode.fps`：24 / 25 / 30（项目默认）；**导出时网页下拉可覆盖**，ffmpeg `-r` 与 concat 时长用导出 fps
- `encode.height`：720 / 1080 / 2160，导出时 `scale=-2:height`
- 可选 `camera_night` + `night_switch_at`（`HH:MM`）

不再做设计稿里的「mode 与间隔硬警告 / allow_auto」那套校验；方案 YAML 给出合理默认，现场在 Web 里改。

## 5. 相机

- still：`create_still_configuration`，main 为所选分辨率 RGB888，lores 960×540 YUV420，`buffer_count=2`
- 旋转 180°：`Transform(hflip=True, vflip=True)`
- 对焦：`manual` 或 `auto_once`（启动时可跑一轮 AF）
- 曝光 / 白平衡 / HDR / EV 等通过 Picamera2 controls
- Web「相机设置」仅未拍摄时可开；与拍摄、空闲预览共用 `_operation_lock`
- 空闲实时预览会保持相机开启；**开始拍摄**时若相机已开，先 stop，再等待约 1 秒后 start，降低 `Camera __init__ sequence did not complete`

开发与测试：`tests/test_runtime.py` 等使用继承 `CameraService` 的假相机。

---

## 6. 调度

- `next_slot` / `advance_slot`：按 Unix 时间对齐间隔槽；错过的槽 **跳到未来最近槽，不连拍补齐**
- 窗口外：`WAITING`，不写帧
- `event`：手动开始到停止之间拍摄
- 暂停：`PAUSED`，恢复不追赶
- 定时：`schedule_start`；可选 `stop_at`；写入 `state.json`，进程起来后 `arm_schedule`

## 8. 恢复

项目目录 `state.json` 记录状态、失败次数、定时时刻等。服务 `lifespan` 里若上次为 capturing/waiting/starting，则 `resume_required` → `start()`。

注册表：`/var/lib/pi-timelapse/active_project` 与 `project_roots.yaml`。

## 9. Web API（摘要）

页面：`GET /` → `index.html` + `/static/app.js`

| 区域 | 路径 |
| --- | --- |
| 启动数据 | `GET /api/bootstrap`、`GET /api/status` |
| 项目 | `POST /api/projects`、`switch`、`GET/PATCH/DELETE /api/projects/{id}` |
| 拍摄 | `POST .../capture/start|pause|resume|stop`、`schedule`、`clear-restart`、`test`、`focus` |
| 调参 | `GET/PATCH /api/camera/tune`，`session` / `commit` / `close` / `auto` |
| 预览 | `GET /api/preview.jpg`、`/api/latest-thumbnail.jpg` |
| 相册 | `GET /api/photos`、缩略图、全图、删除 |
| 导出 | `POST /api/export`（fps + 水印）、`GET /api/export/download`、项目 exports |

预览：空闲走实时 JPEG；拍摄中返回最新已保存帧（避免与连拍抢相机）。

认证：无。仅局域网。

## 10. 导出

- ffmpeg concat demuxer + 每帧 `duration = 1/fps`
- `-vf scale=-2:{encode.height}`，可选 ASS 水印（`PlayResX` 按高度 16:9 偶数宽）
- `-r` 使用本次导出 fps（24/25/30）
- `libx264`、项目 `crf`、`+faststart`
- 水印：无 / 时间戳 / 文本（≤50 字），位置七档

一次只允许一个导出任务。

## 11. 可观测性

Web 运行概览：帧数、间隔、窗口、最后拍摄、剩余空间、CPU、温度、内存、最新缩略图。  
日志：`journalctl -u timelapse`。  
无独立 NTP/RTC 守护；时钟依赖系统 timedatectl。

## 12. 测试

`pytest`（`pythonpath=src`）。覆盖配置校验、窗口与槽位、存储与相册、运行时启停/预览互斥/调参写入、Web API、导出水印与 fps。真机相机不在 CI 里测。

## 13. 部署要点

见仓库根目录 [部署配置指南.md](../部署配置指南.md)。关键约束：

- 原生 venv 必须 `--system-site-packages`（系统 `python3-picamera2`）
- Docker 镜像同样在容器内建带 system-site-packages 的 venv，并安装 apt 的 picamera2；须在 **arm64 树莓派** 上构建
- 原生 systemd 与 Docker Compose **不要同时运行**
- 同步代码时 **排除 `.venv`**，勿 `--delete` 掉派上的虚拟环境（Docker 构建上下文已 ignore）
- 默认端口 **8080**；素材路径在 Docker 下须落在已 bind 的 `/mnt`、`/media` 或自定义挂载上

## 14. 与拍摄设计的对应关系

| 设计原则 | 实现 |
| --- | --- |
| 项目即一次拍摄配置 | `project.yaml` + 注册表，同时只激活一个项目 |
| 锁定焦/光/色 | 相机设置写入项目；可关 AE/AWB、手动对焦 |
| 窗口 | always / clock / solar / event |
| 不追赶漏拍 | `advance_slot` |
| 原图是资产 | 只导出 MP4，不删 frames（除非用户清空或相册删除） |
| 隐私暂停 | pause / resume |
| 倒装 | 旋转 180° |
